Scope and capture method

“All dialogs” includes the application pages/forms represented by all 40 templates, eight booking variants, and shared drawer/search/help/confirmation/offline dialogs. Shared confirmation layouts are shown in standard, reason, and linked-person variants; repetitive confirmation wording is not a separate layout. This is a representative state catalogue, not every possible record or error.

Both exact Git revisions run with the same synthetic fixtures in separate databases. No real bookings are used. Component crops omit unrelated fixed navigation overlays so tall forms remain unobstructed; full pages and dialogs keep the normal shell. Random setup QR codes are masked equally. Decorative random choices are seeded for matching backgrounds. Authentication/session timestamps can differ and are not design changes. Error/Undo states use explicitly labelled demo markup with each revision’s real shared CSS and scripts. Queue states use synthetic IndexedDB data. No confirmations or financial writes are submitted during capture.

Before already includes the earlier shared machine/person-pool fixes. This comparison is of the latest polish commit only, not of every earlier change in this conversation. Accessible labels and timing changes cannot all be judged from a resting screenshot; relevant notes explain them.
